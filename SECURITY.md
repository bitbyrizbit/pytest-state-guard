# Security Policy

## Reporting a Vulnerability

If you discover a potential security vulnerability in `pytest-state-guard`, please report it through GitHub's **Private Vulnerability Reporting** feature.

Navigate to the repository's **Security and quality → Advisories → Report a vulnerability** option and submit your report privately.

**Please do not disclose security vulnerabilities through public GitHub Issues, Discussions, Pull Requests, or other public channels.**

Private reporting allows the maintainer to investigate the issue and coordinate a resolution before public disclosure.

## Information to Include

Please provide as much of the following information as possible:

- A clear description of the potential vulnerability.
- The affected version(s) of `pytest-state-guard`.
- The Python and pytest versions involved.
- Relevant operating system and environment details.
- Steps to reproduce the issue.
- A minimal proof of concept, if available.
- The potential security impact and conditions required for exploitation.

Do not include real credentials, private keys, personal information, or unrelated sensitive data in your report.

## Supported Versions

Security fixes are provided for the latest stable release of `pytest-state-guard`.

Users of older releases should upgrade to the latest stable version before reporting an issue that may already have been addressed.

| Version               | Security Support |
| --------------------- | ---------------- |
| Latest stable release | Supported        |
| Older releases        | Not supported    |

## Response and Disclosure

The maintainer will make a best-effort attempt to acknowledge and investigate submitted reports.

Response and remediation timelines may vary depending on the severity, reproducibility, complexity, and available resources.

If a vulnerability is confirmed, the maintainer will work toward an appropriate fix and coordinate its disclosure with the reporter.

Please allow reasonable time for investigation and remediation before making vulnerability details public.

## Non-Security Issues

For ordinary bugs, compatibility problems, feature requests, and usage questions that do not involve a security vulnerability, please use the repository's public GitHub Issues or Discussions sections.
